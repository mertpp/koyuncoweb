Design Koyun as an editorial luxury wardrobe operating system where typography creates hierarchy, sections live outside cards, cards only contain content, and the experience feels closer to a curated archive or journal than to a SaaS dashboard.

# Koyun Design Language

## Product Philosophy

Koyun is not a dashboard, admin panel, inventory manager, or analytics tool.

Koyun should feel like:

- A personal wardrobe operating system
- A curated archive
- A luxury catalog
- A personal journal
- A ledger for clothing

The visual language should feel closer to:

- The Row
- Aesop
- Apple editorial layouts
- Luxury print magazines
- Archival systems

And further away from:

- SaaS dashboards
- CRMs
- Airtable
- Monday
- Salesforce

---

# Core Principle

## Content lives inside cards.

## Structure lives outside cards.

Never place section titles inside large container boxes.

Preferred:

```text
Wardrobe Intelligence

[card]

Collections

[card]

Care & History

[card]
```

Avoid:

```text
[ Wardrobe Intelligence ]

content

[ Collections ]

content
```

The page structure should be defined by typography, not by borders.

---

# Information Hierarchy

## Level 1 — Section Titles

Used for major areas:

```text
Today
Wardrobe Intelligence
Collections
Purchases
Travel
Care & History
Archive
Recommendations
```

Typography:

```text
Font: Newsreader
Size: 32–44px
Weight: Regular
Purpose: Editorial hierarchy
```

Rules:

- Always outside cards
- Always define page structure
- Generous vertical spacing
- Feel like chapter headings in a magazine

---

## Level 2 — Card Titles

Used inside cards:

```text
British Heritage Winter
Brand / Atelier
Material Spec
Care Protocol
```

Typography:

```text
Font: Geist Sans
Size: 16–18px
Weight: 600
```

Rules:

- Functional
- Clear
- Secondary hierarchy

---

## Level 3 — Metadata

Used for:

```text
CORE CATALOG
CARE INDEX
SPECS MATRIX
12 COMBINATIONS AVAILABLE
```

Typography:

```text
Font: Geist Mono
Size: 11–12px
Case: Uppercase
Tracking: Wide
```

Rules:

- Archival feeling
- Technical feeling
- Low visual weight

---

# Card Philosophy

Cards contain information.

Cards do not define the page structure.

A card should feel like:

- A sheet of paper
- A catalog entry
- A ledger record
- An archival document

Not like:

- A dashboard widget
- A KPI box
- A SaaS component

---

# Layout Rules

## One Level of Cards Only

Good:

```text
Section

[Card]
```

Bad:

```text
Section

[Large Card]
    [Card]
    [Card]
    [Card]
```

Avoid card-inside-card systems whenever possible.

Maximum readability.
Maximum calmness.
Maximum elegance.

---

# Dashboard Philosophy

The dashboard is not a dashboard.

The dashboard is "Today".

The question is not:

```text
What is happening?
```

The question is:

```text
What should I do today?
```

Example:

```text
Today

[Today's Recommendation]

Wardrobe Intelligence

[Card]

Collections

[Card]

Care

[Card]

Purchase Opportunities

[Card]
```

Sections organize the page.
Cards contain the information.

---

# Visual Density

Prefer:

- Whitespace
- Typography
- Alignment
- Rhythm
- Proportions

Avoid:

- Excessive borders
- Section containers
- Nested boxes
- Dividers everywhere
- Visual noise

The interface should feel calm, premium and expensive.

---

# Mobile Strategy

Desktop and mobile share exactly the same design language.

Do not redesign the hierarchy for mobile.

Only change:

```text
Desktop = multi-column layout

Mobile = single-column layout
```

Everything else stays consistent.

---

# Visual Identity

Koyun should feel like:

- An editorial product
- A luxury brand tool
- A wardrobe archive
- A personal assistant
- A timeless object

Koyun should not feel like:

- A business dashboard
- A reporting tool
- An inventory manager
- A spreadsheet interface
- Enterprise software

---

# Design Test

Every new screen should pass this test:

> Does this feel like a luxury wardrobe journal and personal wardrobe operating system?

If it starts feeling like:

- Analytics software
- Reporting software
- Admin software

Then the design is moving away from the Koyun language.

---

# Golden Rule

Typography creates hierarchy.

Cards contain content.

Sections live outside cards.

The page should feel closer to a curated editorial archive than to a modern SaaS dashboard.
